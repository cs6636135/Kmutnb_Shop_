7.1 ขอบเขตและวิธีทดสอบ

ทดสอบระบบแบบ System Testing ครอบคลุม CRUD, Authentication, Authorization, Validation, Error Handling, Search and Filter และ Security รวมถึง workflow การจองและการจัดการสต็อก

เครื่องมือ: Django TestCase, Django Test Client, PostgreSQL, Python 3.13.12

คำสั่งที่ใช้: python manage.py test --keepdb --verbosity 2

ผลจากการรัน python manage.py test --keepdb --verbosity 2: Ran 68 tests in 212.241s — OK (Passed 68, Failed 0, Error 0)

7.2 Coverage Overview

  • CRUD: create, read, update และ delete สินค้า หมวดหมู่ จุดจำหน่าย สต็อก บัญชี และ reservation
  • Authentication: login สำเร็จ/ผิดพลาด และ logout
  • Authorization: anonymous, staff และ admin รวมถึงการจำกัด stock ตาม location
  • Validation: ราคา category รหัสนักศึกษา quantity และ stock ติดลบ/ซ้ำ
  • Business Logic: location ผิด, reservation หมดอายุ และการควบคุม stock
  • Search & Filter: สินค้า staff stock reservation category และ location
  • Security: CSRF, ปลอม ID ลบข้อมูล และแก้ stock ข้าม location
  • Performance (Additional Test): query budget ของ reservation list ไม่เกิน 10 queries และ product detail ไม่เกิน 12 queries

Trigger คืน stock ที่ตรวจแล้ว: สร้าง reservation, status lookup, reservation list และ product detail — ทั้ง 4 จุดผ่าน test เฉพาะทาง

7.6 Manual Test

TC-NFR-07-01 เป็น Manual Test: เปิดหน้ารายการสินค้าและหน้ารายละเอียดบนจอ 360px, 768px และ 1366px; ตรวจว่าไม่มีเนื้อหาล้นแนวนอน ข้อความสำคัญอ่านได้ และปุ่มค้นหา/เลือกสินค้า/จองกดใช้งานได้ ระบุผลเป็น Manual จนกว่าจะทดสอบจริงด้วยผู้ตรวจ

TC-NFR-09-01 ตรวจว่าหน้ายืนยันแสดงข้อมูลระบุตัวตนที่ผู้ใช้กรอกตามการทำงานของระบบ (รหัสนักศึกษาหรือเบอร์โทรศัพท์) โดย Requirement ไม่ได้กำหนดให้ปกปิดรหัสนักศึกษา

7.7 Additional Tests

Additional Test คือกรณีไม่มี Requirement รองรับโดยตรง เช่น ความเร็ว Query, CSRF และการตรวจค่าราคาหรือรูปแบบข้อมูลนอกขอบเขตข้อความ Requirements ไม่ได้สร้าง NFR เพิ่ม

เคสเหล่านี้อยู่ท้ายตาราง Test Cases และไม่ถูกนับเป็น Coverage ของ Requirement
